# Schema — قوانین ویکی دانش این پروژه

این فایل قوانین ساختار و لینک‌گذاری `docs/wiki/` را برای پروژه‌ی **میزان (Mizan)** نگه می‌دارد.
منبع این قالب: Vault Recipe عمومی نقطه. جزئیات کامل قوانین در پایین تکرار شده تا این پروژه مستقل بماند.

## ساختار پوشه
```
docs/wiki/
  schema.md      # همین فایل
  overview.md    # یک‌نگاه کلی پروژه (≤۴۰۰ کلمه)
  index.md       # کاتالوگ همه صفحات
  log.md         # تاریخچه append-only (جدیدترین در پایین)
  entities/      # هر entity مهم یک صفحه (router، parser، engine، client، model، صفحه کلیدی UI)
  concepts/      # patternها، flowها، تصمیم‌های معماری
  sources/       # (اختیاری) خلاصه فایل‌های خام پرارجاع
```

## شروع هر مکالمه/سشن روی این ریپو
1. اول `overview.md` و `index.md` بخوان.
2. فقط صفحات مرتبط با تسک فعلی را drill-down کن.

## وقتی کد را تغییر دادی — قانون اکید
هر بار فایلی در `backend/`, `landing/`, `docs/PRD.md`, `docs/ARCHITECTURE.md` تغییر کرد:
1. entity/concept مرتبط را در `docs/wiki/` به‌روز کن (امضای تابع، endpoint جدید، env var جدید، edge case).
2. اگر entity/concept کاملاً جدید و به‌اندازه کافی مهم است، صفحه جدید بساز و در `index.md` لینک بده.
3. یک خط در `log.md` اضافه کن: `## [YYYY-MM-DD] update | <خلاصه تغییر>`.
4. آپدیت‌های ویکی را یک‌بار در پایان مکالمه انجام بده، نه بعد از هر فایل.

تغییرات trivial (typo، فرمت) نیاز به آپدیت ویکی ندارند.

## چه وقت صفحه جدید بساز
- فقط اگر ≥۳ جای دیگر قرار است به آن لینک بدهند، یا concept مستقلی با حجم قابل‌توجه است.
- در اکثر موارد به‌جای فایل جدید، صفحه موجود را آپدیت کن.

## ساختار صفحه‌ی entity
```markdown
# {نام}

> یک‌خطی توضیح هدف.

## مسئولیت‌ها
- ...

## وابستگی‌ها
- [[concepts/xxx]] — چرا

## قراردادها / Edge cases
- ...

## منابع کد
- `path/to/file.py:42` — توضیح
```

## قواعد لینک (Obsidian-style)
- `[[entities/xxx]]` بدون پسوند `.md`.
- نام فایل: lowercase + hyphen.

## نکته
اگر این قانون رعایت نشود، ویکی stale می‌شود. هدف: دانش فشرده و به‌روز، نه مستندسازی برای مستندسازی.
