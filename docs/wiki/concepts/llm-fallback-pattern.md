# Concept: الگوی Fallback بدون کلید LLM

> چرا و چطور MVP میزان بدون `LLM_API_KEY` قابل اجرا و تست است.

## چرا
تحلیل ریسک واقعی به LLM نیاز دارد، اما توسعه/تست/دمو نباید به داشتن کلید API گره بخورد.
راه‌حل: [[entities/risk-engine]] همیشه یک مسیر دوم (`_rule_based_fallback`) دارد که فقط با regex روی متن کار می‌کند —
بدون شبکه، بدون کلید، deterministic.

## چطور فعال/غیرفعال می‌شود
- [[entities/llm-client]]`.is_configured()` فقط چک می‌کند `LLM_API_KEY` env ست شده یا نه.
- اگر ست نشده یا فراخوانی LLM با هر استثنایی شکست بخورد → بی‌صدا سوییچ به fallback.
- مصرف‌کننده (API caller) از طریق فیلد `analysis_mode` (`"llm"` در برابر `"rule_fallback"`) می‌تواند تشخیص دهد کدام مسیر اجرا شده — اما این فیلد فقط در بدنهٔ پاسخ است، جایی به‌صورت متریک/لاگ عملیاتی surface نشده.

## محدودیت شناخته‌شده
fallback **جایگزین** تحلیل LLM نیست — فقط الگوهای کلیدواژه‌ای پرتکرار را پرچم می‌زند (۵ قاعده ثابت). دقت پایین‌تر و بدون context پروفایل سازمان.
این محدودیت در `summary` خروجی هم به کاربر گفته می‌شود.
